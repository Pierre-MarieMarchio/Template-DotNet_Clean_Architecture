# Overview

## What it is

This project is a .NET 10 HTTP API built on Clean Architecture: a domain, an application layer of
use cases, infrastructure modules behind ports, and a thin presentation layer.
<!--#if (postgreSql)-->
It stores its data in PostgreSQL through EF Core, answers every failure with a problem document, and
refuses to start on a setting it cannot use.
<!--#endif-->
<!--#if (sqlServer)-->
It stores its data in SQL Server through EF Core, answers every failure with a problem document, and
refuses to start on a setting it cannot use.
<!--#endif-->
<!--#if (sqlite)-->
It stores its data in a SQLite file through EF Core, a development database it refuses to run on
outside Development, answers every failure with a problem document, and refuses to start on a
setting it cannot use.
<!--#endif-->
<!--#if (anyWeb)-->
A pnpm workspace beside it holds its web apps.
<!--#endif-->
<!--#if (presentationBlazorServer)-->
A Blazor Web App beside it calls the same use cases in its own process.
<!--#endif-->
<!--#if (presentationAvalonia)-->
An Avalonia desktop app beside it calls the API through a .NET client generated from its document.
<!--#endif-->
<!--#if (presentationMcp)-->
An MCP server beside it offers the same use cases to an agent's client, as tools.
<!--#endif-->
<!--#if (presentationWpf)-->
A WPF desktop app for Windows beside it calls the API through a .NET client generated from its document.
<!--#endif-->
<!--#if (jobsWorker)-->
A worker beside it runs the background jobs, which the API leaves to it.
<!--#endif-->

It is a starting point. The modules and mechanisms it carries are meant to stay; the product's own
features grow beside them, and the documentation grows with them.

## How this project was generated

This project was generated by version 0.0.0-checkout of `CleanArch.WebApi.Templates`, the
`dotnet new` package that also holds `cleanarch-webapp`, `cleanarch-webpackage` and
`cleanarch-presentation`.

## Why it starts like this

The project inherits choices made before any feature existed: the stack, the tools, the
foundations shipped ahead of their first use, the deployment shape. They are recorded as one decision,
[ADR 0001](../decisions/0001-adopt-the-generated-baseline.md), one row each with its reason. Reversing
a row is a decision of your own, written as an ADR that names the row.

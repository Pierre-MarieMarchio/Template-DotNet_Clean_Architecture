# HTTP API

Every endpoint of this API offers a client the same contract: one version in the path, one error
format, conditional writes on versioned resources, safe retries of a create, and one shape for every
collection. A client learns it once. The routes themselves, and every error code, are in
[the API reference](../reference/api.md).

## Versioning and the OpenAPI document

Every route carries its version in the path, `api/v1/…`, and the path is the only place the version
is read: a query string or a header naming another version is ignored. Every response reports
`api-supported-versions`. No response carries a `Deprecation` or `Sunset` header while one version
ships, since either would announce a schedule nobody has committed to;
`HttpSurfaceTests.NoResponse_AnnouncesItsOwnDeprecation` holds it until a second version exists.

The API describes itself with one OpenAPI document per version, generated by
`Microsoft.AspNetCore.OpenApi`. In Development the document is served at `/openapi/v1.json` and
Scalar renders it at `/scalar`. Its summaries come from the XML documentation of the controllers and
the contracts, which the generator reads only in the assembly that calls `AddOpenApi`: that call
stays in `Program.cs`.

The reviewed contract is that document, committed under
`Tests/Integration/AppTemplate.Api.IntegrationTests/OpenApi/`. `dotnet run Tools/Tasks.cs openapi`
writes it from a build, and `OpenApiDocumentTests` fails while the document the API serves differs
from it, naming each difference. A change to a route, a contract or a summary therefore lands with
its new reference, and the review reads what a client will read.
<!--#if (anyWeb)-->
The web apps' API client is generated from the same document, written at build time
([ADR 0019](../decisions/0019-one-generated-api-client.md)).
<!--#endif-->

## Errors and codes

Every failure is a problem document with a stable, dotted `code`. A client branches on `code`, never
on the prose in `detail`, which is not part of the contract. One situation always answers the same
status and code, on every endpoint.

<!--#if (accounts)-->
Another user's resource is answered exactly as a missing one, `404`, never `403`: a `403` would
confirm that the id exists.

<!--#endif-->
[Request pipeline](request-pipeline.md#problem-details) lists the members every problem document
carries, and [the API reference](../reference/api.md#error-codes) every code.

## Request bodies

Every request body is `application/json`, at most `RequestLimits:MaxRequestBodyBytes`. Any other
content type answers `415` `request.unsupportedMediaType`, and a larger body `413`
`request.tooLarge`.
<!--#if (files)-->
The one exception is `POST /api/v1/files/uploads`, which takes `multipart/form-data` carrying a
file's bytes, up to `Files:ApiUploadMaxBytes` plus 16 KiB of framing.
<!--#endif-->

## Writes: PUT, named operations, PATCH

Each feature chooses how a resource is written. `PUT` replaces a complete representation; a named
operation, such as `POST …/items/{id}/complete`, performs one transition the domain knows by name;
`PATCH` is allowed where a feature's callers want it. Every write goes through the domain's methods
and invariants, never a blind copy of properties.

A feature that chooses `PATCH` takes a JSON Merge Patch (RFC 7396): the patch is merged onto the
stored representation, and the merged result is validated and written. A member set to `null` is
removed and a member the patch omits is unchanged, so the invariants are checked against a whole
resource.

## ETag and If-Match

A resource is versioned when its storage keeps a version, and a feature opts in by keeping one.
A versioned resource publishes its version as a strong, opaque `ETag`
on every read of it and every write that returns it. A collection is never versioned.

| Request | Answer |
|---|---|
| `GET` with `If-None-Match` naming the current `ETag` | `304`, no body |
| A write with no `If-Match` | runs, unless `Concurrency:IfMatch` is `Required`: then `428` `precondition.required` |
| A write whose `If-Match` names the current version | runs |
| A write whose `If-Match` is stale, unknown or weak | `412` `precondition.failed` |
| A write with `If-Match: *` on a resource that is missing or not the caller's | `412` `precondition.failed` |
| A write whose `If-Match` is not a list of quoted tags | `400` `precondition.malformed` |

Whatever the header said, a write that loses a race between its load and its commit answers `409`
`concurrency.conflict`: reload, and apply the change again.

```http
GET /api/v1/{resource}/{id}
ETag: "AAAABw"

PUT /api/v1/{resource}/{id}
If-Match: "AAAABw"
```

## Idempotency-Key

A client that retries a create through a flaky network sends an `Idempotency-Key` header, an opaque
string of at most 128 characters, on an action that accepts one.

<!--#if (anyFeature || localAuth)-->
| Action | Accepts a key |
|---|---|
<!--#endif-->
<!--#if (todoLists)-->
| `POST /api/v1/todo-lists`, `POST /api/v1/todo-lists/{id}/items` | yes |
<!--#endif-->
<!--#if (reminders)-->
| `POST /api/v1/todo-lists/{id}/items/{itemId}/reminders` | yes |
<!--#endif-->
<!--#if (files)-->
| `POST /api/v1/files` | yes |
| `POST /api/v1/files/uploads` | no: the body is the file, and a retried upload creates a second file |
<!--#endif-->
<!--#if (notes)-->
| `POST /api/v1/notes` | yes |
<!--#endif-->
<!--#if (localAuth)-->
| the authentication endpoints | never: replaying a sign-in would keep a token at rest |
<!--#endif-->

| Situation | Answer |
|---|---|
| First use of the key | the request runs |
| Same key and body, after it completed | the original status, body, `Location` and `ETag`, with `Idempotency-Replayed: true`; nothing runs again |
| Same key, a different body | `409` `idempotency.keyReused` |
| Same key while the first is still running | `409` `idempotency.inProgress` |
| Same key after the first attempt failed | the request runs: a failure releases its claim |
| A stored response too large to keep | `409` `idempotency.notReplayable` |
| A key on a request with no identifiable caller | `400` `idempotency.callerNotIdentifiable` |

Keys are scoped per user, so two callers may use the same string. A completed key stays replayable
for `Idempotency:Retention`, and the maintenance job purges the expired ones.

<!--#if (publicApi)-->
This API identifies no caller, so it accepts no key; an action marks itself `[Idempotent]` once
callers exist.
<!--#endif-->

## Collections

A collection endpoint takes a closed contract: a caller asks only for what the feature declared,
and anything else is a `400` with a code naming the rule it broke, never a clamp or a guess.

| Parameter | Meaning |
|---|---|
| `sort` | `field[:asc\|:desc]`, comma-separated, from the feature's whitelist |
| `paging` | `offset` (default) or `cursor` |
| `page`, `pageSize` | 1-based page, and its size within the feature's bound |
| `cursor` | the `nextCursor` of the previous page, in cursor mode |
<!--#if (todoLists)-->
| `search`, `createdAfter`, `createdBefore` | the to-do lists' own filters |
<!--#endif-->

A value of the wrong type never reaches the feature: binding refuses it with
`request.validationFailed`. Each rule of the contract has its own code: `paging.invalid`,
`sort.invalid`, `filter.invalid`, `cursor.invalid`.

The metadata lives in the body, which every client already parses: `items`, `pageSize`, `page`,
`totalCount`, `totalPages`, `hasNextPage` and `nextCursor`. No `Link` header repeats it
(`HttpSurfaceTests.NoResponse_CarriesALinkHeader`).

### Sorting and filtering

Sortable fields are a whitelist each feature declares in its `ICollectionPolicy`, with its default
sort, its page sizes and its number of terms. A field name is canonicalised against the whitelist in
the application, and persistence turns it into a column through an exhaustive `switch` whose default
arm throws, so no caller string reaches a query. Each sortable field has an index that leads with
`OwnerId` and ends with `Id`, and `Id` closes every `ORDER BY`, so rows with equal keys never swap
between pages.

Filters are typed query parameters, never an expression language: a grammar the client composes is a
query planner, an injection surface and a performance cliff this project would then own. A new
filter is a new parameter and its test. Free-text search runs in the database, with `%`, `_` and `\`
escaped.

### Offset paging

`page` and `pageSize` answer `totalCount` and `totalPages`, which a page-number interface needs.
The cost: a row inserted before the reader's position shifts the pages, and a deep page is slow
because the database still walks the rows it skips.

### Keyset paging

`paging=cursor` resumes after the last row served, so an insert elsewhere cannot shift the position,
and page 500 costs what page 1 costs. It answers no `totalCount`, which would scan the whole match
set, and allows one sort term, on a field the policy marks keyset-capable; a nullable field is never
one.

The cursor is opaque but not signed: it carries only values from a row the caller was already
served, and the query still filters on the owner. It is bound last, against the order it was minted
under: a cursor sent under another sort, or with offset paging, is refused, and a tampered one
answers `cursor.invalid`, never a `500`.

## Caching headers

A `GET` or `HEAD` answers `Cache-Control: private, no-cache`: a response may be stored by its caller
and must be revalidated, with `If-None-Match`, before reuse. An action marked `[NoStore]` answers
`no-store`. Every response varies on `Authorization` and `Origin`, so a shared cache can never serve
one caller's response to another. A value an endpoint sets itself is never overwritten.
